# Product website

The [GitHub Pages website](https://alreadyontv.com/) introduces AlreadyOn to homelab testers and provides a nontechnical feature overview, a detailed WebUI/app walkthrough (`guides.html`), and a homelab technical guide (`technical.html`). `help.html` explains Issues and Discussions. Its source lives in `website/`. It is a companion to the application, with no accounts, analytics, remote fonts or application API access.

Run `python3 scripts/build-website.py` to produce `_site/`. The build checks local pages, asset references and anchor targets. Preview that generated folder with a temporary static HTTP server. Paths are relative so the site works under GitHub Pages’ `/AlreadyOn/` prefix. Homepage links use the directory URL with section fragments; old `index.html` bookmarks retain their fragments while the browser displays the clean URL. The build uses only Python’s standard library. Screenshot filenames include a content hash; replacing a capture changes its published URL, avoiding stale browser/CDN images. Both inline images and enlarged dialogs use the versioned URL.

The organization site publishes from `AlreadyOnTV/alreadyontv.github.io` using its Pages workflow. Dispatch that workflow with `source_ref` set to the tested application repository commit or branch (currently `26.10.18`). It checks out the public application repository and runs this build script; no cross-repository write token is needed. Site source stays in this primary checkout. The old application-repository Pages workflow publishes redirects, preserving project-site page links and fragments at the root address. Dispatch it when redirect rules change.

Website publication does not authorize application promotion, image publication or live-server deployment. Both Pages workflows have independent deployment environments. Verify the root site and legacy redirects after publication.

Screenshots are real WebUI and native Android renders with isolated synthetic demo media. See `website/assets/screenshots/README.md` for provenance. Capture replacements against disposable fixtures, never a persistent library or owner account. Website CSS supplies framing and subtle gloss; do not fabricate product controls or claim untested device acceptance.

Release descriptions live on GitHub, and review snapshots stay outside the repository. Keep beginner guidance consistent with the deployment, TLS and Android references. Public support links point to `AlreadyOnTV/AlreadyOn`; internal development tickets remain in the designated development tracker. Check mobile layouts, keyboard navigation, tabs, screenshot dialogs, copy controls and external destinations before publication. Verify the deployed page and assets afterward.
