# Dependency maintenance

Dependabot checks Go, npm, Android/Gradle and GitHub Actions every Monday at 03:00 America/New_York. Weekly Dependency Updates runs at 06:30, or manually, and combines every open same-repository Dependabot PR targeting `dev`, including major versions, into one maintenance PR. Updates arriving afterward enter the next batch. Dependency pin/lock changes need no prose unless they change a public contract; other source changes retain documentation requirements.

The combined commit must pass quality, CodeQL, full synthetic Go/browser e2e, disposable packaged-runtime checks, phone/TV compilation, unit tests and lint, plus source/runtime/CI vulnerability and secret scanning. Validation has no signing or publication secrets. Write-token jobs execute only trusted helpers and combine proposals through GitHub's merge API. Conflicts or failed checks stop integration; original proposals remain open. Critical/High findings, secret matches and scanner failures block delivery. Unfixed upstream findings require repair or a reviewed exception, not automatic dismissal.

Integration fast-forwards `dev` to the exact tested commit without force. Concurrent dev changes invalidate the batch; branch protection remains enforced. Incorporated Dependabot PRs close only when their heads still match the tested snapshot. The job explicitly dispatches nightly delivery because workflow-token ref updates do not trigger push workflows. Delivery repeats the full gates and publishes Docker `nightly` plus signed phone/TV `YY.MM.DD-nightly` APKs. A date's published nightly is immutable; another source on that date requires a new date. Publication failure never promotes a release stage; inspect Actions and retry the exact source after repair.

`test`/`latest` and `main`/`stable` promotion requires the maintainer's request after nightly acceptance. No weekly job deploys, publishes alpha/RC/Stable, refreshes base images merely to hide findings, or dismisses alerts. Docker promotion reuses the tested digest; APK stage builds preserve the tested source and signing identity.

Weekly Dependency Review remains an independent read-only Monday 03:17 baseline scanner. It records published image digests, source, manifests and tool versions for 90 days; raw secret/vulnerability reports stay private to the ephemeral runner. The daily cleanup watchdog checks both weekly workflows and fails without a successful scheduled run in eight days; manual runs cannot conceal missed schedules. Both depend on GitHub scheduling. Inspect Actions independently and enable failure notifications.

Workflows must reach the default branch before schedules activate. Verify a real scheduled batch and review; local policy tests do not establish scheduler operation. Toolchain and base-image upgrades still require compatible locks and builds. See [scanning](VULNERABILITY_SCANNING.md), [delivery](CI_CD.md) and [Android releases](ANDROID_RELEASES.md).
