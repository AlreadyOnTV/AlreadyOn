# Dependency maintenance

Dependabot checks Go, npm, Android/Gradle and GitHub Actions every Monday at 03:00 America/New_York, grouping updates per ecosystem. Weekly Dependency Updates combines open same-repository Dependabot proposals targeting `dev` on a temporary validation branch; updates arriving later enter the next batch. Dependency pin/lock changes need no prose unless they change a public contract; other source changes retain documentation requirements.

The workflow summary links the combined diff and original PRs; Actions needs no permission to create or approve PRs. The combined commit must pass quality, CodeQL, full synthetic Go/browser e2e, disposable packaged-runtime checks, phone/TV compilation, unit tests and lint, plus source/runtime/CI vulnerability and secret scanning. Validation has no signing or publication secrets. Write-token jobs execute only trusted helpers and combine proposals through GitHub's merge API. Conflicts or failed checks stop integration; original proposals remain open. Critical/High findings, secret matches and scanner failures block delivery. Unfixed upstream findings require repair or a reviewed exception, not automatic dismissal.

Integration advances only `dev` to the exact tested dependency batch. Concurrent dev changes invalidate the batch; incorporated Dependabot proposals close only when their heads match the tested snapshot. A later dev-to-main PR runs the normal release gates before Nightly publication. Same-date Nightly reruns replace assets only after all gates pass and allocate higher APK codes.

Stable publication is a separate manual workflow on `main`. No weekly job publishes Stable, deploys, refreshes base images merely to hide findings, or dismisses alerts. Stable reuses the latest Nightly image digest and builds fresh APKs with the same source and permanent signing identity.

Weekly Dependency Review remains an independent read-only Monday 03:17 baseline scanner. It records published image digests, source, manifests and tool versions for 90 days; raw secret/vulnerability reports stay private to the ephemeral runner. The daily cleanup watchdog checks both weekly workflows and fails without a successful scheduled run in eight days; manual runs cannot conceal missed schedules. The new integration workflow gets until 24 hours after its first Monday slot; a failed scheduled run still fails immediately. Workflow creation time fixes that deadline, so manual runs cannot extend it. Both depend on GitHub scheduling. Inspect Actions independently and enable failure notifications.

Workflows must reach the default branch before schedules activate. Verify a real scheduled batch and review; local policy tests do not establish scheduler operation. Toolchain and base-image upgrades still require compatible locks and builds. See [scanning](VULNERABILITY_SCANNING.md), [delivery](CI_CD.md) and [Android releases](ANDROID_RELEASES.md).
