# Android app updates

Phone and TV release builds check public GitHub releases on startup. Stable installs select stable releases; other signed release installs accept alpha, RC and stable. Because promotions reuse the preview APK bytes/version name, an installed APK with a matching published stable counterpart follows stable releases automatically. Checks use version codes, so promotions that reuse APKs do not prompt again. Drafts and non-Android release tags are ignored. Checks inspect up to ten pages of thirty releases; failed/offline checks stay quiet.

GitHub requests use system HTTPS trust without server credentials, cookies or LAN certificate exceptions. Downloads are bounded to 256 MiB in app-private storage. Only the project repository's release URLs and GitHub's release asset hosts are accepted. APK SHA-256, package, exact version, target marker and installed signing certificate must match before installation. Certificate rotation requires a reviewed updater change; unrelated signing keys fail closed.

`android-release.json` retains its existing fields and adds `artifacts.phone` and `artifacts.tv`, each with `file` and `sha256`. New APKs declare `io.github.alreadyonapp.alreadyon.UPDATE_TARGET` as phone or tv. Both APKs share an application ID; this marker prevents crossing targets. Older descriptors without explicit artifacts are skipped by the updater, but remain valid for release promotion.

Update/Cancel is available before sign-in and uses touch or remote focus. Cancellation stops download/abandons the install session. Android unknown-source permission and installation confirmation remain user decisions. A staged session and expected version are persisted before commit; commit starts only while the app is resumed. Installer callbacks or package replacement attempt relaunch. OS restrictions may require Open/manual launch. On replacement or next startup, the installed version is checked before removing the APK and pending state. Orphaned downloads and failed sessions are removed separately. Account/profile/session storage is untouched.

Debug packages do not query production releases. The first updater-enabled release must be installed manually. Physical phone and TV testing is required before claiming device compatibility. Test network/corrupt/wrong-target failures, denied permission, cancellation, process death, settings continuity, successful replacement and cleanup. See [Android](ANDROID.md) and [release policy](ANDROID_RELEASES.md).

Run `python3 scripts/android/test-updates.py --serial EMULATOR_SERIAL --sdk SDK_DIRECTORY` on an emulator for synthetic phone/TV updater tests. Add `--java-home JDK_DIRECTORY` if the default Java is unsupported by Gradle. It creates a separate test package, verifies signed APK target/version and download failures, exercises dialogs, replaces version 23 with 24 through Android approval, and checks settings/cleanup. It removes only its new synthetic packages.
